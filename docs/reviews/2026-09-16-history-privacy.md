# 已授权历史清理阶段审查

## 范围及结果

独立只读核查本地清理脚本、5 对提交映射、备份、替代历史、当前文件和计划发布方式：

- 提交消息、作者/提交者时间、父提交拓扑保持不变，身份统一为核实的昵称与 noreply。
- 仅历史 README 和 DEVELOPMENT_SPEC 中的身份目录做专项替换，其他历史文件的 mode/type/blob SHA 不变；最终完整源码树与原开发 HEAD 完全相同。
- 原 HEAD 在本地 archive 精确保留，不包含在发布引用中；修改后的旧签名移除，不冒充有效签名。
- 完整提交 header/message 与 197 个不同历史文件对象扫描，个人资料/邮箱/路径、API Key、私钥及常见 Token 模式未发现命中。模式检查并非穷尽泄露证明。

未发现待发布内容的阻断问题。发现清理脚本重复运行可能覆盖原 archive 的本地复用风险；已加入仅首次创建和不同 HEAD 拒绝重跑的保护，并验证拒绝重跑后原备份不变。

## 发布控制

只发布 main、原迁移分支和工单开发分支三条明确引用；原子更新并逐引用验证精确旧 SHA，使用 force-with-lease。禁止 --all、--mirror、--tags 或附带本地 archive。远端有新提交时停止更新并重新核查，不能覆盖新工作。

远端更新仍需系统 Git 登录，结果以实际远端引用及重新扫描为准。清理分支可达历史不等于删除 GitHub 缓存或别人已有克隆。
