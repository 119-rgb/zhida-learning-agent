# 隐藏工具过程与执行异常设计

## 目标

实时聊天只呈现回答计划与最终答案，不再逐条展示联网搜索、网页读取、知识库检索及其技术细节，也不再把任务异常显示成红色“执行遇到问题”分析步骤。

## 方案

- 后端继续产生并持久化工具事件和任务失败状态，保证调用预算、任务状态、历史审计与排障能力不受影响。
- 前端实时事件处理忽略 `tool.started`、`tool.completed`、`tool.failed`，只保留通用的“正在查找和整理”状态提示。
- 收到 `task.failed` 时，不把异常详情追加到回答或分析步骤；隐藏分析卡片。若没有任何回答内容，只显示中性的“暂时没有生成完整回答，请重新提问。”
- 浏览器请求本身失败时同样不追加红色分析步骤，保留简短可操作的回答区提示和顶部状态。
- 历史执行记录仍保留在用户主动展开的诊断入口中，不影响后台排查。

## 边界

- 不改变 Agent 是否调用搜索、网页读取或知识库，只改变实时界面的呈现。
- 不吞掉后端错误，不改变任务的 `FAILED`、`CANCELLED`、`INTERRUPTED` 状态。
- 用户主动停止时继续显示“已停止回答”，因为这是用户操作反馈，不是内部执行细节。

## 测试

- 增加前端展示契约测试，确认实时处理函数不再调用工具过程渲染函数。
- 确认任务失败分支不再添加红色分析步骤或暴露后端异常消息，并会隐藏分析卡片。
- 运行完整 Maven 测试和打包检查。
